Add canonical OAuth callback decoding and validation (`OAuth.callbackParamsFromQuery`, `OAuth.callbackParamsFromFormPost`, `OAuth.validateCallback`) in `@yielded/oauth`, wire them across `@yielded/auth` HTTP and proxy callbacks, and enforce atomic `responseMode` binding in OAuth flow persistence.

BEHAVIOR CHANGE: Direct HTTP and proxy `response_type=code` callbacks now reject unsolicited front-channel token parameters (`id_token`, `access_token`, `token`, `token_type`, `expires_in`, `response`), cap `form_post` bodies at 16 KiB raw bytes, accept `user` only on `POST`, always admit standard callback parameters (`state`, `code`, `error`, `error_description`, `error_uri`, `iss`, `scope`) plus `Http.make`'s provider parameters (`authuser`, `prompt`, `hd`), forward `OAuthCodeResponse.scope`, and return `Cancelled` while clearing `request-binding` for every bound provider error. Expected issuer validation uses the `OAuthIssuer` issuance contract (including well-formed Unicode) rather than discovery URL rules, failing closed at `begin` before issuing any flow. Observed callback transport is server-owned: named JSON completion endpoints record `"query"` (with no public `response.mode` field), dedicated callback routes derive `"query"`/`"form_post"` from GET/POST, and custom server-side `form_post` callback hosts must provide `OAuth.OAuthCallbackTransport`. Mapped SQL/Drizzle tables must bind nullable `OAuthFlowTable.responseMode`, replacement persistence services must compare observed `access.responseMode` inside the same conditional delete (`NULL`/omitted strictly for native sign-in), and development environments should add the nullable `response_mode` column to managed `${prefix}_oauthSignInFlows` / `${prefix}_oauthConnectedFlows` tables (or recreate those tables and clear in-flight browser flows; durable accounts, sessions, identities, and grants are unaffected).
